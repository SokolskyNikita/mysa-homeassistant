# Cloud integration policy and validation

Last reviewed: **2026-10-12**, Mysa Local **0.5.2**.

This page records Home Assistant cloud integration scope, recovery behavior, and
hardware evidence. The [Mysa client API inventory](https://github.com/SokolskyNikita/mysa-client/blob/main/docs/api-coverage.md) owns direct
requests, response decoding, encoders, protocol evidence, and raw API gaps. The
[HA management map](https://github.com/SokolskyNikita/mysa-homeassistant/blob/main/docs/implementation/progress.md) owns source selection, command handling,
recovery, and cross-protocol acceptance criteria.

The client supports three cloud API varieties: structured services, legacy REST
on the modern host, and legacy REST on the older host. Route details and method
coverage now live with the client. HA acquisition runs the selected sources,
keeps per-field observations, and applies a bounded host fallback only where
verified. It does not treat host aliases as independent measurements or replay
ambiguous commands. See the linked management criteria for the integration
rules.

## Validation limits

The strongest live evidence covers two Baseboard Lite `BB-V2-0-L` thermostats
on firmware `3.17.5.13`, observed October 10–12. Selected local/cloud controls
and temporary schedule workflows were exercised. Their cloud setpoint/mode
application differed, and no offered firmware release was installed during
those checks. AC, In-floor and other baseboard profiles need matching hardware;
V3, Central HVAC and Climate Sensor mappings remain experimental. See
[MGT-QUALITY acceptance criteria](https://github.com/SokolskyNikita/mysa-homeassistant/blob/main/docs/implementation/progress.md#mgt-quality-01).
