## Design Context

### Users

Coverage documentation serves this project's maintainer, contributors, and people
evaluating the reusable Mysa client. They need to distinguish available protocol
operations from the integration's management of state, commands, and failures.

### Brand Personality

Professional, precise, and visually engaging. The user asked for a professional
progress graphic, then supplied a dense two-panel tiled coverage map as the
reference for a more expressive version.

### Aesthetic Direction

For coverage diagrams, use an ink-dark background, restrained green/amber/slate
status colors, crisp geometric tiles, compact group labels, and readable totals.
Organize real inventory items into labeled regions, following the supplied
system-library/GPU coverage reference. Keep generated SVGs self-contained and
usable in repository Markdown.

### Design Principles

1. Give raw API support and integration management separate inventories and scores.
2. Every coverage tile represents one named inventory item; never inflate density
   with decorative items or imply a bug-free percentage.
3. Keep the overall comparison readable before exposing individual details.
4. Use text, shapes, and accessible descriptions alongside color.
5. Generate visuals from the maintained inventory and check for stale output.
